# Community surfaces

Use the surface that matches the work:

- **Issues** track reproducible defects, accepted features, documentation work, and concrete maintenance tasks in the repository that owns the change.
- **Discussions** are for questions, design exploration, support, ideas that are not yet actionable, and community showcases.
- **Projects** show prioritized and scheduled work. A Project item does not replace a repository issue.
- **Wikis** provide maintained onboarding, development, security, and FAQ material. Versioned Wiki sources live in each repository under `docs/wiki`.
- **Pull requests** implement a real same-repository issue and must use a recognized closing reference such as `Fixes #123`.
- **Security reports** must follow [`SECURITY.md`](SECURITY.md) and must never be filed as public Issues or Discussions.

Automated pull requests are exempt from issue linkage only when their actor login exactly matches an entry in `governance/repositories.json`. Repository-specific contribution and security policies take precedence where they are more restrictive.
